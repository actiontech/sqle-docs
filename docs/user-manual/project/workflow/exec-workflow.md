---
title: 上线工单
---

工单通过所有审核节点后，进入上线环节。上线人可根据实际场景选择不同的上线方式执行 SQL 变更。

## 前置条件

- 工单状态为 **待上线**
- 当前用户为该上线节点的指定上线人

## 查看待上线工单

- **Dashboard**：在首页 Dashboard 的待办区域点击「需上线」标签
- **工单列表**：进入项目工单列表，筛选状态为「待上线」

![工单列表](img/list.png)

## 上线方式

### 1. 立即上线

| 方式 | 说明 |
|------|------|
| 批量立即上线 | 工单涉及多个数据源时，一次性对所有数据源同时执行上线 |
| 单个数据源上线 | 仅对选定的数据源执行上线 |

### 2. 定时上线

选择 **定时上线** 并设置上线时间，平台将在指定时间自动执行。适用于需要避开业务高峰期的场景。

设置后可随时取消定时上线，重新选择上线方式。

### 3. 标记为人工上线

已在后台手动执行过 SQL 的场景，可通过 **标记为人工上线** 直接更新工单状态，无需平台再次执行。

## 上线操作

上线人进入工单详情页后：

1. 确认工单内容无误
2. 选择上线方式并执行
3. 查看执行结果

:::tip
- 以文件模式上线 ZIP 文件时，可在上线前手动调整 SQL 文件的执行顺序
- 上线过程中可点击 **中止上线** 按钮中断执行，避免影响正常业务
:::

| 操作 | 说明 |
|------|------|
| **执行上线** | 按选定方式执行 SQL 变更 |
| **全部驳回** | 上线人发现问题时，驳回工单并填写原因，工单返回至创建人 |

## 执行结果

上线完成后，工单详情页展示每条 SQL 的执行状态（成功 / 失败）和执行耗时。

若开启了 SQL 备份，可在执行结果中查看备份信息，并在需要时进行 [回滚操作](rollback.md)。
